# خدماتي V8 — Security Hardened

## ما تم في V8
- منع القراءة المباشرة لجدول `coupons` من `anon` و`authenticated` حتى لا تظهر أكواد الخصم وقيمها عبر REST.
- منع استدعاء `validate_coupon` من الزائر غير المسجل، مع إبقائه متاحًا للمستخدم المسجل.
- الإبقاء على التحقق الفعلي من الكوبون داخل قاعدة البيانات.
- الحفاظ على `confirm_payment_webhook` كدالة غير متاحة للمستخدمين، لتُستدعى من Edge Function باستخدام `service_role`.

## قبل الإطلاق
1. نفّذ `schema.sql` كاملًا على مشروع Supabase جديد/نسخة اختبار أولًا.
2. ضع `supabaseUrl` و`supabaseAnonKey` فقط في `config.js` — لا تضع `service_role` في الواجهة.
3. اربط `paymentFunctionUrl` و`pushFunctionUrl` بعد نشر Edge Functions.
4. اختبر التسجيل، إنشاء الطلب، الدفع، الـWebhook، الاسترداد، التقييمات، النزاعات والإشعارات بحسابين تجريبيين.
5. لا تعتبر النسخة إنتاجية حتى تنجح اختبارات الـSupabase والـWebhook على بيئة حقيقية.

## ملاحظة
النسخة تعمل في وضع Demo عندما تكون إعدادات Supabase فارغة. هذا مفيد للعرض، لكنه ليس بديلًا عن إعداد Backend حقيقي عند الإطلاق.
