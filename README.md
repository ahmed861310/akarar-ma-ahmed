# خدماتي V3.4 — المحفظة والدفع

هذه النسخة تضيف طبقة مالية داخل المنصة فوق V2.3:
- 💰 محفظة للمستخدم.
- 💳 دفع داخلي تجريبي لطلبات مقدمي الخدمات.
- 🧾 سجل عمليات مالي.
- 📈 احتساب صافي ربح مقدم الخدمة بعد عمولة خدماتي.
- 🏦 تجهيز قاعدة البيانات لطلبات سحب الأرباح.
- 🔒 دالة Supabase آمنة لتنفيذ الدفع والتحويل الداخلي.

## مهم جداً
زر «شحن تجريبي» في الوضع التجريبي فقط، ولا يمثل أموالاً حقيقية.
لا تعتبر هذه النسخة بوابة دفع حقيقية ولا تجمع بيانات بطاقات بنكية.
للدفع الحقيقي يجب ربط مزود دفع مع خادم آمن وWebhooks والتحقق من العمليات.

## تشغيل الوضع التجريبي
افتح `index.html` مباشرة. زر «تجربة سريعة» ينشئ حساباً برصيد تجريبي 1000 جنيه.
يمكنك تجربة سوق الخدمات، إنشاء طلب، ثم الدفع من المحفظة.

## تشغيل الوضع الحقيقي
1. أنشئ مشروع Supabase.
2. نفّذ `schema.sql` بالكامل.
3. ضع Project URL وanon public key في `config.js`.
4. أنشئ حساب المستخدم ثم حوّله إلى مدير عبر SQL كما في النسخ السابقة.
5. قبل الإطلاق التجاري، اربط بوابة دفع حقيقية عبر Backend/Webhook ولا تضع مفاتيح سرية في الواجهة.

## المسار التجاري المقترح بعد V3.3
بوابة دفع حقيقية → Escrow/حجز المبلغ → تسليم الخدمة → عمولة المنصة → تحرير أرباح مقدم الخدمة → طلب سحب → لوحة مالية للإدارة.


## V3.3 — الوساطة المالية (Escrow)
- عند دفع طلب مقدم خدمة، المبلغ يُحجز في حالة `held` ولا يصل لمقدم الخدمة فوراً.
- بعد أن تصبح حالة الطلب `تم التنفيذ`، يستطيع العميل الضغط على «تأكيد استلام الخدمة».
- عند التأكيد، تُحسب عمولة خدماتي ويُحرر صافي المبلغ لمحفظة مقدم الخدمة.
- الإدارة تستطيع لاحقاً رد المبلغ المحجوز عبر دالة `refund_request_payment`.
- الدفع والشحن الحاليان في الواجهة تجريبيان؛ لربط أموال حقيقية يجب استخدام بوابة دفع وخادم آمن وWebhook للتحقق من العمليات.


## V3.3 — لوحة تحكم الإدارة الاحترافية
- مركز إدارة موحد للطلبات والمستخدمين ومقدمي الخدمات والماليات.
- مؤشرات الأموال المحجوزة والمحررة والمستردة وعمولات المنصة.
- إدارة حالات الطلبات واسترداد المدفوعات المحجوزة.
- متابعة طلبات سحب أرباح مقدمي الخدمات.
- بحث داخل كل قسم.
- في الوضع التجريبي تعمل اللوحة محلياً.
- في وضع Supabase تعتمد صلاحيات الإدارة على RLS و`is_admin()`.

> ملاحظة: الدفع والسحب الحقيقيان يحتاجان ربط بوابة دفع وخادم آمن. لا تضع مفاتيح `service_role` داخل الموقع.


## V3.3 — الإشعارات الفورية
- جدول `notifications` مع RLS للمستخدم صاحب الإشعار فقط.
- Trigger في Supabase ينشئ إشعارات عند إنشاء طلب، تغيير الحالة، تحرير الأرباح أو الاسترداد.
- الواجهة تعرض عداد الإشعارات، قائمة آخر التحديثات، ونافذة إشعارات كاملة.
- في الوضع الحقيقي تستخدم الواجهة Supabase Realtime لتحديث الإشعارات فور وصولها.
- في الوضع التجريبي توجد محاكاة محلية للإشعارات.
- بعد تشغيل `schema.sql` تأكد من تفعيل Realtime لجدول `notifications` في مشروع Supabase إذا لم يكن مفعلاً.


## V3.4 — المحادثات
- محادثة مرتبطة بكل طلب بين العميل ومقدم الخدمة.
- رسائل فورية عبر Supabase Realtime عند تشغيل الوضع الحقيقي.
- RLS يمنع قراءة أو إرسال الرسائل لغير أطراف الطلب.
- إشعار تلقائي للمستلم عند وصول رسالة جديدة.
- الوضع التجريبي يحفظ المحادثات محلياً.
